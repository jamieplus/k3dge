# 落 ADR：投影三维契约（目标 × 语法 × 范围）

- **可检索摘要**: `docs/memo/archive/2026-09-16-orchestration-form-exploration.md` 的 S6/S7 已定型但未成 ADR。内容＝**投影三维契约**：① 目标（判断主体 → 成对选项；进程 → 闭集判定）② 语法（有应答通道 → 疑问句；无 → 陈述句）③ 范围（引用必须便携）；外加双主体铁律的**消费侧延伸**（产：进程永不判断；消：判断主体给选项、进程给机械步）与词汇精度约束。

## 意图

把 memo 的持久设计固化进 ADR。memo 自己写的下一步是「1–3 做完再拿实际结果写 ADR」——1–3（ADR 归档移出封板 / 引用便携 / 便携性测试）均已完成，故 ADR 到期。

## 待落内容（源：memo S6 / S7）

| 维 | 由什么决定 | 约束 |
|---|---|---|
| **目标** | 谁消费 | 判断主体 → 背景 + 成对选项；进程 → 闭集判定 |
| **语法** | 有无应答通道 | 有（`prompt.ask` 读 stdin）→ 疑问句；无（`[NEXT]` 纯打印）→ 陈述句 |
| **范围** | 在哪个仓消费 | 引用必须便携（不得依赖「只有本仓才成立」的事实） |

配套三条：

1. **双主体铁律的消费侧延伸**：现有 ADR-0006 §2.3.6 只管「产」（进程永不判断；判断须署名席位）；补「消」（投影给判断主体 → 选项；给进程 → 机械步）。
2. **可编排性判别**：可编排 ⇔ 该过程的「归属」与「判断」在同一主体内，且该主体就是编排者。⇒ **agent 的工作流不可被 k3dge 编排**（否则剥夺其判断，违 ADR-0009 本意）。
3. **词汇精度**：`席位` ＝署名判断者（审计人/透镜来源/验收），**不含 agent**（agent＝使用者，人＝维护者）；`投影` ＝派生视图、由源重生成、从不手填（ADR-0025 语境），**不可拿来指消费者**。
