# Memo: 图论视角在审计/项目优化上的应用（为 audit vs QA 职责讨论铺底）

> **Legacy note（归档 2026-09-12）**: 落地项已转票：k3dge `feat-task_dag_lens`/`feat-state_machine_lens`、k3dit `feat-graph_metrics_layer`、k3che `feat-cooccurrence_cluster`；边表抽取器 `import_graph`/`cycles` 已落（k3dit）。§6 路由表/§7 理论编排作设计地图留存。

- **类型**: 暂无法落地（下一步维护者讨论 audit/QA 职责划分时作输入，届时逐条定归属再转 tasks）
- **念头**: 审计与优化的多数对象天然是图（依赖/控制流/状态机/工单/文档引用）。图论给的不是新工具，而是**把"看起来乱"换成可机检的图性质**：成环、可达、闭包、扇入扇出、等价态。本篇把散在各仓的图论应用整理到一处，并标出每格现状（✅已有 / 🟡判据级(人/席执行) / ❌无）。
- **触发场景**: 2026-09-05 会话，维护者问"audit 有没有图论 lens"、补充"状态机优化"，并预告下一步讨论 audit(k3dit) 与 QA(k3lity) 的职责界限——界限模糊处恰是"图的哪些性质归判断、哪些归确定性"。
- **Date**: 2026-09-05

## 2. 元观察：每条图论应用都必须拆三段（这是 audit/QA 界限的试金石）

任何一格落地都自动切成三段，**三段归属不同仓**：

1. **图事实**（边表/可达集/环列表/度分布）——确定性计算 ⇒ k3lity 或 k3dge（静态零 LLM）；
2. **形态判读**（这个环要紧吗、这个扇入是热点还是巧合、这个死状态是预留还是废弃）——判断 ⇒ k3dit 透镜；
3. **闸语义**（要不要因此阻断/提示/只观测）——门禁策略 ⇒ k3dge（check/`[NEXT]`/WARN）。

界限模糊的根源：**大家把"跑了个图算法"当成一个整体决策**。它不是——`SCC 找到 3 个环` 是事实，`M7 这环违背 ADR` 是判断，`因此红你 commit` 是闸。下一步讨论 audit/QA 职责时，建议逐条图应用过这三段问，比按"审计/质量"名义分要准。

## 3. 本仓已核实事实（2026-09-05，防下次误引）

- k3lity `_branch_count`（`quality.py:49`）= 分支启发计数，**不是** `E−N+2P`；k3dge C2（`audit_trigger.py`）= 控制流**嵌套深度**，不是 CC。三者别混称"圈复杂度"。
- 全仓无图算法库、无 import 图/SCC/可达性实现（grep `import graph|cycle|dependency` 仅命中 tree-sitter 注释与散文）。
- k3dit 现 12 透镜（`mcp.py:39-52`）、测试 53 绿；k3lity 测试 20 绿。
- task `blocking` 字段：契约声明了（peer_contract §9），引擎无消费者。

## 4. 与下一步讨论的接口

audit vs QA 职责划分讨论时，建议开场先对齐一句工作定义草案（来自 §2 的拆分）：**QA(k3lity) = 图事实的确定性生产者；审计(k3dit) = 形态判读的输出者；k3dge = 拿前两者的话决定闸的语义**。模糊地带逐个用三段问审判归属，不整体判。

> **本节措辞已被 §5 取代**（Hall/ADR-0025 对齐后 k3dit/k3lity 旧名消失，按窗重分配）。三段拆法本身仍有效。

## 5. Hall 对齐后的修订（2026-09-05 晚，ADR-0025 定案后）

- 三段归属改词：① 图事实 → **审计模块工具面**（并入原 k3lity 能力）或大厅规则典（check 域）；② 形态判读 → **4 判读窗**（代码审计/文档审计/价值/复核）；③ 闸语义 → 大厅规则典 + 人章（W5）。k3che 仍独立（共现簇候选不变）。
- **图论 ≠ 过程审计的一种**——两者不同层：图论是工具面手段，过程审计是复核窗的对照面之一。按"对照物"分流：**对照声明/账本的图**（工单 DAG、状态机转移图、证据链时序图——"改码→审计→修复→复核→seal 不可逆"本质是时序可达性检查）→ 判读半喂**复核窗**（过程审计因此获得可机检武器：席只对差集判断）；**对照代码的图**（依赖、控制流）→ 代码审计窗/价值窗；文档引用图 → 文档审计窗。
- 判据仍是声明可比性：有声明等着被对照的图进过程审计供料线，没有声明但可数的进内容审计供料线，都不可数的才是纯裁量。

## 6. 图应用 → 窗路由表（2026-09-05 定稿）

**总形态：图论不散落在窗里各用一点，而是"工具面一组图分析器 + 一张按对照物的路由表"，四判读窗都是消费者。** 前提三条件（缺一退化为仪表板）：可节点化 + 有声明可比 + 建图忠实（建图本身是第 0 段判断，归席/人）。

| 应用 | 图事实（工具面，确定性） | 判读落窗 | 说明 |
| --- | --- | --- | --- |
| 性能优化 | 调用图热路径、扇入热点 | 代码审计窗 | 8 族策略是判读；图给"往哪看"，量尺裁决归度量纪律（k3lity measurement.md） |
| 去冗余/简化结构 | 扇入扇出、不稳定度 I=Ce/(Ca+Ce)、共现簇、重复 helper 团 | 价值窗 | "该删的复杂度"=结构回退判断 |
| 依赖/import 环 | SCC | 代码审计窗 | Pass 2 DAG；import 图有误报（TYPE_CHECKING/动态），SCC 出 WARN+证据非硬闸 |
| 锁序/wait-for 环 | 锁获取图环检测 | 代码审计窗 | 并发红旗经典应用；席判"锁序约定是否结构性成立"（ADR-0004） |
| 工单 blocking 环 / 流程时序 | 任务 DAG 环检测、证据链时序可达性 | **复核窗**（过程审计供料线） | "改码→审计→修复→复核→seal 不可逆"=时序图可达性；blocking 环=死锁队列 WARN |
| 状态机死状态/非法跃迁 | 转移图可达性/闭包 | **大厅规则典**（有转移表声明可比）；"状态数虚多"→价值窗 | 大半确定性，剩最小化裁量 |
| 文档引用悬空 | 引用图查缺失目标 | 文档审计窗（判读）；确定性半在 check | ADR-0005 已做 |

**落地提醒（诚实账）**：§1 现状列这些几乎全是 ❌——本表是设计地图，不是完成清单。已落地的只有 CC 分支计数（k3lity）与嵌套深度触发（k3dge C2）。落地顺序从复核窗供料起步（blocking 环/状态机可达性：纯静态、零 LLM、声明现成），依赖/锁图工具层次之。

## 7. 数学理论 → 窗编排（2026-09-05，graph 的推广；判据同三段问 + 建图忠实三条件）

**原则：不发明判据，理论化到现成学科。** 完整映射已同步 k3dit `protocol.md`「窗口与透镜对口」理论源列；此处留全景与排除账。

**第一梯队（已编排进对口表）**：
- 形式语言/自动机/时序逻辑（LTL）→ 复核窗 + 大厅规则典（"不可逆/终态可达"=性质检验）
- 流程挖掘（Petri 网/conformance checking）→ **复核窗直接理论化**：rounds 状态机+本 ADR 时序=声明模型，账本/logs=事件日志，席只判对齐差集
- 格论/不动点（抽象解释、数据流、污点、锁序格）→ 代码审计窗工具面（现成库多，gen/kill 可直接实现）
- SDT/ROC → over-report 校准的形式化（ADR-0004"宁少勿误"=调判定阈工作点）；误诊率指标进观测面

**第二梯队（可落地，未编排，候选）**：
- 信息论：NCD 压缩距离做代码克隆检测（去冗余定量版，工具面可算）；熵做重复度
- 统计/抽样：ISO 2859 审计抽样（token 预算读不完时带置信度抽样——传统审计师已解决此问题）；控制图→窗口漂移监测（度量回灌那格的理论化）
- 组合优化：审计选文件=背包（注意力预算下最大期望发现）；席位调度=二分匹配；回归面=set cover
- 集合代数：findings 去重（Jaccard）；闭包计数本身=集合运算

**第三梯队（明确排除，防再提）**：
- 拓扑数据分析（代码形状）——论文有工程薄，无声明可比
- 博弈论/机制设计——章笔分离已是机制设计产物；同信任域（ADR-0006 S-13）无对抗博弈可言
- 贝叶斯网络——置信分层（ADR-0005）已够用，形式化证据更新收益不明、成本高
- 编码论——契约哈希已是检错码形态，无增量

**共同前提（不过则退化为仪表板）**：可节点化 + 有声明可比 + 建图/建模忠实（第 0 段判断归席/人）。

### 7.1 实现映射（不重复造轮子，除非自造更简单——原则 2026-09-05 定，政策正文在 k3dit protocol「工具面实现政策」）

| 应用 | 首选实现 | 层级 |
| --- | --- | --- |
| blocking 环 / 依赖环 / 拓扑序 | **stdlib `graphlib.TopologicalSorter`**（CycleError） | stdlib，零依赖 |
| 状态机可达性 / 死状态 / 转移闭包 | 自造 dict+BFS（声明小且固定） | 自造豁免（§实现政策第 4 条） |
| 引用悬空 / 文档图 | 现有 `k3dge_adr_index` 扩展 | 已有 |
| 严格 McCabe CC | radon（optional extra，口径=真 `E−N+2P`） | 外部校验器，禁自写第三套 |
| NCD 克隆检测 | `zlib` 压缩距离 | stdlib |
| 严格 conformance（若流程模型长大） | pm4py（**仅当**声明模型复杂化才升 optional） | 默认不引 |
| 审计抽样 / Jaccard 去重 / 控制图 | `random` / `set` / 单文件小实现 | stdlib/自造 |
| 席位调度（当前 seats.toml 规模） | 自造贪心 | 自造豁免（规模 < 匈牙利算法价值） |
