# Memo: 大厅模式推演账（2026-09-05，为 ADR-0025 与角色分工讨论作废案账）

> **Legacy note（归档 2026-09-12）**: 权威正文已落 `ADR-0025`；本档仅存推演/选项/废案，判定以 ADR-0025 为准。

- **类型**: 暂无法落地（输入：维护者下一步讨论"角色具体分工"；届时把每格过三段问，再转 tasks）
- **念头**: 从"审计 vs 质量如何划分职责"一路推到"harness 拓扑要不要合并"，最终模型=市政大厅：harness 只是场地不持判断权，权威在各窗口（席位）。本篇记推演里被否掉的形态与放宽条件，防止下次讨论重走旧路。
- **触发场景**: 2026-09-05 会话。维护者先问 audit/quality 职责划分，后连续提出并、合并编排，"少一个 harness"；被连续问"我不同的宇宙该不该并进 audit 自治"。
- **Date**: 2026-09-05

## 1. 结论先写（决策本体在 ADR-0025，Proposed 待判）

> **时效注（2026-09-06）**：本节 §1 的窗口列举（分诊/契约/验收窗）已被 ADR-0025 后续修订取代——现行：判读窗=代码/文档/价值/复核（复核=验收+过程审计），契约/分诊不入窗，统计席位归进程侧。以 ADR-0025 正文为准，本节留作推演痕迹。

- 大厅 = 单一确定性调度进程（叫号/物化/收集/验签/推进/通告牌），无判决口径。
- **窗口 = 合并后审计模块的职责单元**，按「判断类型 × 对象」划分，不按来源（k3dit/k3lity 旧名消失，能力资产重新分配）。分**两族**：判读窗群（分诊 / 契约 / 代码 / 文档 / 价值 / 验收，各独立钥/发布轨）与**行动窗（修席窗）**（无签名钥、无独立发布轨，唯一 repo 写权，只改物+翻 `fixed`+`fixnote`）。
- **大厅只组织窗口、不亲自干活**：修复活由修席窗（行动窗）接——"谁修等价"是能力等价 ≠ 不设窗。
- **验收独立**：翻 `fixed` 后由验收窗（另窗、独立授权）Retest，判读窗不自提自验。
- **seal 仅大厅门槛**，接受权 = 人。

## 2. 明确的废案（不再讨论的形态）

| 形态 | 为何废弃 | 首次提出/否掉 |
| --- | --- | --- |
| 审计 + 质量 + k3dge 编排全并 = 一个大利益团体自行判断 | 判断权威集中=自审塌缩；被审物主权（ADR-0025 主权四章）破裂；封板变自我声明 | 维护者提，Agent 否 |
| 单席角色扮演（一个席位演多角色） | 独立性=假象；笔和章不分 | 维护者自己澄清排除，"各干各的" |
| 外聘"第三方监督审计机构"（真实世界的 PCAOB 形态） | 现实已证：2002 前"内部监督自治"被证伪才加了外部检查；本项目再外搭一层纯属剧场 | Agent 建议时即否 |
| 合并"纸张"（接口/运输/报告面）连"部门权威"一起并 | 政务中心可信前提=税务和房管是两家；合并部门=假装两个局 | 维护者认"信封归一类、判断归两类" |
| 合并后仍按 k3dit/k3lity 分成"两个判读窗"（合署办公） | 那不是合并，只是塞进一个进程；划分应按「判断类型×对象」的窗口，不按来源 | 维护者否，改窗口划分 |
| 修席拥有独立判断权威（签名钥/发布轨） | 修不是判断；agent 语境可重建，能力等价；修席只需行动约束，不需要判断身份 | 否 → 修席=行动窗（保留窗口一员，去掉判断属性） |
| 删除修席窗、修复=大厅自持能力 | 大厅是场地只组织不干活；有能力即施工队；修活必须落窗口 | 维护者否 → 修席窗保留（行动窗） |
| "回原判读窗复核"修复结果 | 判读窗自提自验=失独；Retest 客观性要求独立验收方（四眼原则） | 维护者否 → 验收独立成窗 |

## 3. 讨论里出现但未定的命题（下一步分工讨论的输入）

> **时效注（2026-09-06）**：分诊/referral 相关条目已裁决（分诊不入窗，见 ADR-0025 §2.2），不再是未定项；度量回灌已归进程侧 G8。剩余未定：修复队列优先级启发式、回归面选择规则、度量口径。

- 每窗方法论细节与流转参数未定：修复队列优先级启发式（严重度×优先级）、回归面选择规则（blast radius → 重喂复核窗）、度量口径（误诊率 / 泄漏率 / 窗口漂移）。
- 行业对标三列对账（保留/优化/新增）已立为底线：k3dge 已有机制（bundle 一袋即宇宙 + 主权四章、12 列 + provenance/baseline、双盲 + 机器不自签 + 审计钉棘轮）只能被优化不可丢失。
- 大厅分拣 = 按窗 scope 把**同一个 bundle**物化裁剪到各窗目录（读裁剪：只读送检包 / 只读包+清单 / 可写 scratch / 修席唯一 repo 写权）+ 按调度序推进（叫号→收集→验签→推进）。操作对象只有一个 bundle，分的是窗；没有多通道，"路由"只是 scope→目录映射表（ADR-0025 §2.2 物化裁剪）。
- 度量回灌 = 考评前序处理能力的**观测**（误诊率/泄漏率/窗口漂移）：只进通告牌 + 审计窗判读材料，不进闸、不中途改单，作用于下一单/下一轮校准。
