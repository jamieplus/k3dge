# ADR-0026: 投影契约（对 agent 的三维投影与三层拓扑）

## 1. 上下文 (Context)

k3dge 的输出有两类消费者：**进程**（机械变换，可复算）与**判断主体**（人／席位，须署名）。agent 属后者，同时又是 k3dge 被使用的环境——k3dge 说什么、怎么说，决定 agent 是越权判断还是漂移。

现有条款只覆盖一半：

- ADR-0006 §2.3.6 双主体铁律管**产出侧**（进程永不判断；判断落具名席位；无署名不过闸）。
- **消费侧无条款**：同一条事实投影成什么形状，`[NEXT]`、`prompt.ask`、scaffold 模板各写各的。
- **跨仓消费无条款**：下游仓的 `AGENTS.md`／rules 引用本仓事实时，写法是否成立无人判。

已成立却只写在代码里的约束（`src/k3dge/engine/nextstep.py`）：`success -> state; failure -> action`、`Never decide for the human`、`only legal options, no "now execute seal"`。无对应 ADR，改投影面时无判据可依。

实测支撑：`k3dit`／`k3che` 的 `AGENTS.md` 各有 4 处 ADR 引用在本仓不成立（引用不可移植）；`[NEXT]` 是纯打印面，无应答通道。

来源：`docs/memo/archive/2026-09-16-orchestration-form-exploration.md` 的 S6/S7（探索记录，判定以本文为准）。

## 2. 决策 (Decision)

### 2.1 三层拓扑：谁可被编排

| 对象 | 关系 | k3dge 角色 | 机制 |
| --- | --- | --- | --- |
| 席位的原子调用 | 一次动作 | 客户端 | `pipeline.toml` 的 stages |
| k3dge 自身的步 | 可编排 | 拥有者 | `gates [checks.*]` |
| agent 的工作流 | 不可编排 | 仪表 | `nextstep` 的 `[NEXT]` |

**可编排性判别**：可编排 ⇔ 该过程的「归属」与「判断」同属一个主体，且该主体就是编排者。
⇒ k3dge 只给 agent **事实 + 合法选项**，不编排它的步骤；替它编排即替它判断（违 ADR-0009 本意）。

### 2.2 投影三维契约

同一件事实投影成什么形状，由三个正交维度决定：

| 维 | 由什么决定 | 约束 |
| --- | --- | --- |
| **目标** | 谁消费 | 判断主体 → 事实背景 + **成对**选项；进程 → 闭集判定 |
| **语法** | 有无应答通道 | 有（读 stdin）→ 疑问句；无（纯打印）→ **陈述句 `fact` + 成对 `options`**，禁疑问句 |
| **范围** | 在哪个仓消费 | 引用必须便携，不得依赖「只有本仓才成立」的事实 |

**语法维的判据（为何纯打印面禁疑问句）**：疑问句不客观反映事实——它把发问者预设的默认答案嵌进句式（「封板？」预设了下一步就是封板），于是成为**带主观偏见的引导性话术**；而纯打印面没有应答通道，被引导者连「不」都没处答。故：

- 纯打印面只出 **`fact`（陈述事实 + 决策权归属）+ `options`（合法选项，≥2）**；选项平级陈列，不排序、不标默认。
- 疑问句只允许出现在**真有应答通道**处（`prompt.ask` 读 stdin），且文案必须与 `fact` **同源于一条声明**（`STATE_OPTIONS[state]` 的 `fact` / `question` 两个字段，各投影一次——不是两份文案）。
- 通道行为（`default_yes` / `countdown`）属「怎么问」，留在调用点，不进声明。

### 2.3 双主体铁律的消费侧延伸

ADR-0006 §2.3.6 只管产出侧；消费侧对称补两条，两侧共用同一分类：

- **产**：进程永不判断；一切判断落具名席位。
- **消**：给判断主体 → 提供**合法选项**（不替它选）；给进程 → 提供**机械步**（无分支余地）。

### 2.4 词汇精度

- `席位` ＝ 署名判断者（审计人／透镜来源／验收），**不含 agent**（agent ＝使用者）；人 ＝ 维护者。
- `投影` ＝ 派生视图，由源重生成、从不手填（ADR-0025 语境），**不可用来指消费者**。

### 2.5 非目标

- 不规定投影的文案措辞，也不规定 `prompt.ask` 的 y/N 与倒计时（各命令的局部选择）。
- 不新增机制：无语法检查器、无渲染层。本文只把**已成立的约定**记为不变量（语法维的四条已由 `test_nextstep.TestProjectionInvariants` 守住）。
- 不追溯存量：不符合三维的既有输出面不因此变红；改到哪面才按哪面判。
  - **存量已清（2026-09-19）**：`[NEXT]` 的 5 个疑问句（`pending_findings` / `audit_suggested` / `seal_ready` / `audit_open` / `new_domain`）已改陈述式 `fact` + `options`；疑问句只留在 `STATE_OPTIONS[*].question`，仅由 `prompt.ask`（有 stdin）消费。本条豁免从此空转。

### 2.6 D 线：自主 ↔ 自主不由 k3dge 编排

§2.1 的三层拓扑讲的是"谁可被编排"；本节把**第四种流转**显式判为不可编排，免得下一次有人在 k3dge 里给席位排步骤。

- **判据**（承 §2.1）：可编排 ⇔ 该过程的「归属」与「判断」同属一个主体，且该主体就是编排者。自主 ↔ 自主的归属与判断分属不同自主单位（审席 / 修席 / 复核席 / 人）⇒ 对 k3dge **恒不可编排**。
- **k3dge 在 D 线只做三件事（闭集）**：
  1. **状态可见**：`[NEXT] ratchet_open` / `escalated`；`k3dge audit status|show`。
  2. **事实供给**：`present` / `materialize`（worktree 机械抽取）、账本、钉、`events.jsonl`。
  3. **幂等步进**：`advance`——一次调用推一步，**进程不等人**，绝不在闸里等席。
- **禁止**：给席位排步骤；代签（承 ADR-0006 §2.3.6「机器不自签」）；把 D 线状态塞进 `[checks.*]` 节点表。
- **实例**（现存，编排权都在 k3dge 之外）：Hall 席位圈（`docs/protocols/peer_contract.md` §1.4：判读落钉 → 修翻 `fixnote` → 复核翻 `fixed` → Hall 拔 → `sign-report`）；`escalated` 转人工；Accepted ADR 就地修订需显式人工授权；新建文档判定为"并入"时需宿主 ADR 的授权席位认可。
- **为何仓内看不到 D 线机制**：因为它的编排在 Hall/人那边，k3dge 里只剩仪表与介质。**这不是缺设计，是设计生效的样子。**

### 2.7 骨架声明的下游可配边界

编排声明（`[checks.*]`：preconditions / actions / stages_*）是**下游可配面**——下游仓能改顺序、关步骤、换角色绑定。可配不等于无约束：

- **权威与缺省**：仓内权威 ＝ 该仓自己的声明文件；**代码内缺省必须完整**（`engine/gates.DEFAULTS`）。声明缺失或解析失败 ⇒ 回落缺省，**闸不因配置坏而失效**。下游删掉整段也必须能跑。
- **未知 id 一律拒绝**，不静默跳过（"不让声明空转"）：下游写错 id 要立刻红。
- **两类 id 不混一张词表**：`actions` ＝ k3dge 内部动作 id（注册表）；`stages_*` ＝ 外部 peer 的 action ref（交 `run_action` 走 `mcp→cli→manual/skip`）。ref 用**角色名**（`audit.actions.x`），下游换 `[roles.audit] bind` 即换实现，声明不用改。
- **字节锁的边界**：本仓声明文件 ↔ `src/k3dge/templates/assets/*.template` 受 `PAIRS` 锁；下游拿到的是 init 时的副本，**可自由改、不受锁**。
- **字段即契约**：加字段可以（必须带缺省）；改字段语义 / 删字段 / 改档位默认值 ⇒ 走 ADR（下游既有配置会静默变义）。
- **不可配的部分**（明写，避免"全可配"幻觉）：判据本体（`docs/<type>/.schema.json` 的结构规则、`evaluator` 的检查函数）、投影形状（§2.2 三维）、档位与文案的**词表**（`gate_facts`：code 是 k3dge 自己的，下游不能发明 code）、D 线不变量（§2.6）。下游可配的是"走哪些步、什么顺序、失败怎么办、绑哪个实现"。

## 3. 产生后果 (Consequences)

- **Up**：新增或改动投影面有判据（三维 + 双主体两侧），不再靠各命令自行发挥；跨仓引用可移植成为不变量。
- **Down**：投影面将来长出新形态须回到本文判维度；`[NEXT]` 这类纯打印面无应答通道，语法只能靠审读，测只能守词汇不越界。
- **Reopen when**：出现第四类消费者（既非进程也非判断主体），或出现 stdin 之外的应答通道。
