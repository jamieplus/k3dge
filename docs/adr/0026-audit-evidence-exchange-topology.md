# ADR-0026: 审计证据交换拓扑（审计线 · 一单一条 · 树上钉 · 分支写回）

## 1. 上下文 (Context)

棘轮审计（一单=一快照、单内审↔修交替）确立后，证据如何在 k3dge / k3dit / 席位之间流动成为剩余分歧点。早期推演排除过 MCP 分块上传（自造管道）、"证据随案卷"入 k3dit（违背数据最小化）、ack 驱动 GC（编排越权）（`docs/memo/2026-09-02-peer-wiring-and-seat-options.md` 废案账）。信任前提：同机同信任域（`ADR-0006` S-13），审计不兼任监管——针对"被审方自欺"的防伪件不成立。

2026-09-07 重设计（两次收敛）：第一次从 bundle 单文件退到 store 沙盒直读（袋在本地信任域无真实消费者）；第二次发现沙盒本身也是多余——审计线（分支+worktree）早已在消费仓 `.git` 里实现"一单一条线"的隔离，且**对象格式、树布局与主干天然一致**，写回就是 ff 或重演。独立库+打包器（sha256 库、`target/` 前缀、scrub 树、签名骨架、袋 create/resolve 全套）整体退役。交换物＝**一单一条线**，过渡态的袋/沙盒概念全部作废。

## 2. 决策 (Decision)

### 2.1 主权四章（各归其一，无重叠）

| 物 | 主权 | 依据 |
| --- | --- | --- |
| 证据本体（分支 `k3dit/<单>`＋worktree 现场）与 **GC** | **k3dge**（消费仓）：线从锁点 L 拉起；闸过合主干后删现场删线（仅已并入时），废单删分支——主干从未脏 | 被审物不迁主权；线是消费侧的物 |
| 工单：findings 正文、裁决史、状态机、报告 | **k3dit**：账本只存机构自身的判断物＋引用（baseline=锁点 L、branch、scope），**不存一字节客户代码** | 数据最小化：处理者不因处理而存档委托方资料 |
| 阅件 | **席位**：submit 得 `{baseline, branch, wt_dir, scope}`；Hall 按窗 scope 把现场拷进各窗，轮毕即清（处理≠归档）；席位/机构**永不直接操作消费仓 `.git`** | 同左 |
| 报告 | **审计席位**产出并签署；渲染=机械抽取（账本⋈delta），席位只运行与署名，不重打字 |
| 报告落位 | **k3dge 进程**：按本仓命名规约机械放置 `docs/reviews/`（可复算、可哈希验证，不产判断） | `ADR-0006` 双主体铁律（§2.3.6） |

**裁决签名规则（P3）**：账本状态翻转（`fixed/disputed/leftover` 终局）只能由**审计席位**提交；修席的合法动作=改码＋删/转标记＋登记 `fixnote`。整份报告由审计席**运行抽取脚本**从 delta 生成并署名——判的人写判，修的人只改物，笔和章不分离才奇怪。

### 2.2 交换物：审计线（一单一条）

- **形状**：线＝分支 `k3dit/<单>`（自锁点 L 拉起，住消费仓 `.git`）＋ worktree 现场（`.k3dge/wt/<单>`）。送检＝锁线（`ensure`＋`advance`，脏改动进程代提交）；交件＝字符串句柄（baseline=L/branch/wt_dir/scope）；取件＝机构内部读现场。独立库、打包器、袋、sha256 特殊对象格式——全部退役。
- **钉即交换介质**：判读席在窗拷贝的 src 上按同一套钉书写（`k3dit:<kind> <ID>` 独占一行，交件无钉对应即拒收）；Hall 收三窗钉→去重→落线文件→提版；修席在带钉的线上改（钉是路标只读不删，删钉会上主干）；复核在带钉版上验。席间交换的是树上的钉，JSON 只当签名信封——账本位置列合线时以树上钉水合，12 列仍从账本渲染。
- **隔离是三层拼出来的**：审计线 vs 主干（ref＋本地 exclude＋闸过删线，未并入线原位保留）；窗 vs 窗（Hall 按 scope 拷窗＋CLI 原生 root/deny）；席位 vs 消费仓 `.git`（席位/机构永不直接操作，改动经 Hall 收回、进程 advance 提版）。
- **身份**＝最新线头 commit oid（主干血统、可复算、可 `git log`）。submit 锁 L 只是首钉；Hall 管线每提版（advance）在办单基线即重钉——报告按最新基线签，判读在旧 L 下的工作由复核窗覆盖。案内版本史载体是线本身＋账本判读记录。
- **代价（承认）**：不再有包级脱敏（scrub/target/ 前缀/签名骨架随打包器退役）——审计线是全树 checkout，secret 随现场直穿机构全程；送检范围 targets 退为 Hall 物化参数。同信任域可接受（§1），跨信任域 ⇒ Reopen（§Reopen-when ①）。

### 2.3 写回拓扑：线上最终版合入主干（P1/P2 已拍板 2026-09-04；重演路径 2026-09-07）


- 主干**只在 closure 时**接收合并；**合并默认自动执行，冲突即停并升级人工**——机器负责搬运，人只在物理分歧处出现（P1）。
- 路径：先去钉（钉永不进主干：独占钉行删，行尾钉上报；去钉产物提版）→ ff 直达；ff 不成 ⇒ 线 `(base..L′]` `rebase --onto` 重演到主干头再 ff（真 merge 已废：线提交全是机械件，重演即普通 git）；冲突 ⇒ abort 复原＋升级人工（§1.4）。
- 账本载"判"、分支载"物"：裁决状态权威始终在 k3dit 工单簿，分支不复制真相。
- 轮次分支 ref 住**消费仓 `.git`**（分支是消费侧的物）（P2）。
- 废单=删分支（主干从未脏）；崩溃恢复=分支原位续走；过程留痕=`git log k3dit/<job>`；收口删现场删线（仅已并入时）。

### 2.4 复用与校验

- 跨仓/跨单复用（§7 预筛）按 **oid × lens_version 匹配工单簿结论**——不需要持有客户内容即成立，与最小化自洽。
- 完整性链条：锁点 L 即基线（主干血统、可复算）＋ report `provenance.baseline` 与 L 的形式比对；k3dit 无内容故不做内容验货。

### 2.5 非目标 (Non-goals)

- 不建 k3che 证据/CAS 角色（回归 token 经济，`ADR-0023` §7 v0.5 既定）。
- 不做"镜像/备份"入协议（机构运维手段）。
- 不引入被审方防伪机制（信任域内，§1）。
- 不实现远程部署（服务发现/推拉鉴权等）。远近同形只是包时代的愿景，线时代远程即另题——到实施时另立 ADR，不在本条内预焊。

## 3. 产生后果 (Consequences)

- **Up**：交换物与工作现场合一（线即送检即现场），无打包、无独立库、无双份磁盘、无 sha256 特殊对象格式；对象格式与树布局同主干，合并是普通 git；consuming 侧只认"锁点 L"一个身份。
- **Down**：审计线是全树 checkout——scrub/target/ 前缀/签名骨架随打包器退役，secret 直穿机构全程（同信任域接受，§2.2 代价条）；范围裁剪从内容边界退为 Hall 物化参数；非 git 消费仓无法审计（显式拒绝）。
- **Reopen when**：① 跨信任域部署成真（需封闭集/脱敏通道，§2.2 代价条目兑现）；② 流程出现"多站并行"（同线多站读写同一时点，线生命周期需重审）；③ 冲突升级后的人工 rebase 决策若频繁出错（届时再谈是否收紧自动合并的范围）。
