# ADR-0027: 审计模块（audit+quality）——Hall 确定性编排 + 物理隔离子席位

## 1. 上下文 (Context)

- 三 harness（`ADR-0020`：k3dge / k3dit / k3lity）的审计与质量接口同构（submit / collect / bundle / 12 列报告 / ratchet），一分多主要遗留形式冗余，维护面与部署面重复。
- 治理类比区分两类东西：**场地**（市政大厅/政务中心，只组织周转、无审批权）与**坐馆单位**（各窗口，权威与其独立部门）。审计机构的内部监督天然自治（内审、席位、方法论），不因外部组织存在而成立。
- 信任前提不变：同机同信任域（`ADR-0006` S-13）、防伪不成立、Peer Contract §0 双盲与 §1.4 机器不自签仍需主体分离；被审物主权不迁（`ADR-0026` §2.1 主权四章）。
- 合并编排的争议点：审计方若同时持有/书写消费仓账本、盖封板章，则审计降格为自我声明——合并可行与否取决于"墙"能否从约定变成机制。
- 待办：每窗方法论细节与流转参数（队列优先级、回归面、度量口径）另行讨论（推演账见 `docs/memo/2026-09-05-hall-pattern-discussion.md`）；本 ADR 冻结拓扑、窗口划分与墙。

## 2. 决策 (Decision)

### 2.1 模型：审计模块含大厅子概念（Hall = 确定性编排进程，场地不持有内容判断权）

- 大厅 = 单一确定性调度进程：叫号（闭包计数）→ 物化（按角色裁剪作用域包落目录）→ 收集 → 验签 → 推进 → 通告牌（降级公示）。
- 大厅**无内容判决口径**（不判代码对不对、设计值不值）；只持有程序/一致性判定（台账可复算、隔离可测、降级可见、check 的声明↔实际）与大厅规则典职责。内容判断权威全部落在窗口。
- 判断权威全部落在窗口（席位），各司其职、各自独立授权。大厅部署在物理哪一侧是部署细节，不变量在数据保管与写权（§2.3 W3/W4）。

### 2.2 窗口 = 合并后审计模块的职责单元（按「判断类型 × 对象」划分，不按来源）

- 合并 = 把 audit/quality 的内容**精细编排为一个模块**（同屋檐、多窗多席），不是两套东西塞进一个目录。合并以**窗口**为基本责任单元：签名钥、scope、方法论全部落窗口级（方法论正文可同源如 protocol.md，独立的是判断权不是文本）；k3dit / k3lity 作为历史来源消失，能力资产按窗口重新分配，旧名不再作为模块内划分依据。
- **分离锚点（独立性的全部载体，缺一即角色扮演）**：① W1 目录墙（大厅 spawn 时校验 root+权限）；② 各判断窗签名钥互不相同；③ W5 章在人手。独立性**不依赖**独立工件或独立发布轨（一个模块同一构建可签多产物），但上述三载体必须真实存在且可测。
- 窗口分**两族**：**判断窗群**（有签名钥、独立方法论，裁量管判断）与**行动窗**（无签名钥，只执行改造）。
- 判断窗群（独立钥，各自判读）：**代码审计窗**（健壮性、并发红旗、错误路径、RCA 根因复查；含反例/边界击穿方法选项）、**文档审计窗**（文本质量、悬挂指针、类规约、doc-audit）、**价值窗**（复杂度、重复、过重设计、更简做法——k3lity 可数判据的判断侧）、**复核窗**（对照声明查实际，参数化对照面：findings 验收[Retest 独立] + 流程合规[SQA，审计原义]；验收发现的新问题回执路由，不由复核窗裁决）。
- 契约/分诊不入窗（维护者裁决）：契约一致性（spec↔实现/哈希/ADR 符合性）= check 的确定性声明↔实际，已是大厅规则典职责，非判断；分诊/语义路由=物化阶段参数（大厅按 scope 裁剪送检包给谁），非独立单元。两者都不占判断窗。
- **修席窗 = 行动窗**：大厅只组织窗口、不亲自干活，修改活由修席窗接；修席窗仅「改物 + 翻 `fixed` + 登记 `fixnote`」，唯有它持有 repo 写权；agent 语境可重建，"由哪个修席上下文修"能力等价（≠不设窗）；永不签名。
- 窗与窗隔离为物理层（进程 + 目录）**并叠加 CLI 原生访问控制**：root = 专属目录、权限 **deny-by-default**（根外访问拒绝、无审批路径）；spawn 时注入清洗过的 env（仅本窗签名钥 + 配置摘要）；墙的最终归属是大厅——spawn 时必须校验 root 与权限配置，CLI 只是放大器。
- 物化裁剪：大厅决定什么内容落进哪个目录（只读送检包 / 只读包+清单 / 可写 scratch / 修席窗唯一 repo 写权）。数据最小化的表面在物化。
- **确定性管流程**（调度 / 物化 / 闭包 / 归档）；**自由裁量管判断**（窗口输出天然不确定，现实治理同此——规则内工作人员有裁量权）；**规则管行为边界**（范围 / 能力 / 程序固定、裁量留痕可复核、窗口权威有界：能判"怎么判"，不能改规则 / 闭包 / 计数 / 存储）。三件事不可混为一词。
- **窗序固定（checkpoint，非动态排序）**：语义执行序冻结为 判读（文档→代码→价值：先标尺、后实现、再综合）→ 修席（行动）→ 复核（验收+流程）→ 闭包→seal；打回只回退到修席，不跳窗、不插队、不动态重排。实现层可并行跑判读三窗，但收集/推进按固定序，顺序语义不变。

### 2.3 不变量（墙，机制化、可测）

- **W1 ctx 隔离**：跨窗口泄露 = 大厅失职。隔离借 agent cli 原生机制：窗口 root = 专属目录、权限 deny-by-default（根外与邻窗拒绝、无审批路径）、env 清洗；大厅 spawn 时校验 root + 权限配置。测试：窗内 Read / Grep 根外与邻窗目录 → 断言拒绝。
- **W2 轮间清场**：每轮结束销毁 / 轮换目录，防残留。
- **W3 降级可见**：任一窗口不可达 → `WARN[DOWNGRADE]` 上抛市民；禁止大厅内自愈掩盖。
- **W4 账本主权**：大厅保管**台账原件**（findings/rounds/计数——程序可复算，这是场地唯一"持有"之物）；被审仓的送检快照原件与归档主权在市民侧，归档经市民侧 shim 镜像（`ADR-0026` 主权四章不破）。保管诚实是程序不是判断。**Hall 无自有状态**：调度状态全由账本重放重建（"进程不等人"的常驻版）；Hall 崩溃重启后必须回到同一调度位置，kill -9 演练是 G2 验收项。
- **W5 闭包计数**：seal 接受计数器任何席位不可读 / 不可写；接受权 = 人（章在人手，非任何席位角色）。rounds/findings 台账复核窗只读可读（流程合规核对之用），禁写。
- **W6 活性（空转熔断）**：大厅 spawn 每个窗口**必须**带三重预算——轮数 / token / 无进展次数。无进展 = `(动作签名, 结果签名)` 连续 N 次全等（动作签名 = 命令/目标文件+操作；结果签名 = 退出码/输出哈希/失败测试名；N 默认 3）。计数者是**大厅（进程侧）**，不是席位自我观察——空转的定义即自我意识失效（上下文压缩后看不见前 N 轮），"发现自己一直转"的叮嘱在机制上不可依赖。触发 ⇒ 停机 + `WARN[DOWNGRADE]` + 输出已试签名清单（先落台账再执行 W2 销毁，清单不随目录消失）⇒ 按 escalated 先例转人工；窗口永不自判"再试一次"。推广路径：宿主 hooks 记 tool-call 流水 / 大厅看门狗；check 红×2 与 seal verify >3 是本协议在 commit 侧与 seal 侧的场景化先例。
- **章笔分离**（沿用 `ADR-0026` §2.1 P3）：判断窗群签各自发现；复核窗签验收/流程结论；修席窗永不签名。
- **复核独立（Retest 客观性）**：翻 `fixed` 后由**复核窗**（独立钥）逐条验收 + 流程合规核对，判读窗不自提自验；复核不通过 ⇒ 打回修复、`fixnote` 续记、闭包计数不闭合；复核发现的新问题回执物化路由重定向，不由复核窗裁决。
- **seal 仅大厅门槛**：闭包计数由大厅且仅为大厅；验收全部通过的计数闭合才到 seal；接受权 = 人（章在人手），任何窗口碰不到 seal。

### 2.4 合并边界与行业对标底线（并什么 / 不并什么 / 什么不能丢）

- **并**：大厅（编排 + 调度 + 隔断 + 通告牌 + 叫号）、审计模块（重新编排的 audit+quality，接口=原 audit；大厅为其子概念）。**k3che 不并入**——保持独立 peer（记忆/检索 `learn.py`/`cache.py`/`hit_rate`），与审计模块分界清晰（记忆该不该出现 vs 代码对不对），记忆侧不参与判断；审计模块可照常消费 k3che 检索（独立 peer 调用，G1 保留调用点）。
- **不并**：判断窗群互相之间的**权威**——各判断窗独立签名钥 + 独立席位隔离（§2.2 分离锚点）；"假装两个局"即自审塌缩 ⇒ "假装六个局"同理。工件与发布轨可共享（同模块多产物），锚点在三载体不在工件数。
- **统计席位（程序控制+收尾度量+回归测试）**：归**进程侧**（Hall 确定性程序控制 + 观测，不占判断窗、无签名钥）。送检快照之外的数据走读裁剪；观测只出事实、不判定（观测不判定先例：k3che 观测行、k3dge status）。
- **行业对标三列对账**：拟引入的外部标准要素一律先查对应 k3dge 既有机制，落「**保留** / **优化** / **新增**」三列；**已有设计只能被优化、不可丢失**。三条不可丢基准：一单一条审计线＋主权四章（`ADR-0026` 重设计：线即送检即现场，包/袋/独立库退役）；12 列报告 + provenance/baseline；双盲 + 机器不自签 + 审计标记棘轮。
- **补缺增量**（行业标准指出、k3dge 三方均缺）四块：修席队列优先级（严重度×优先级）、回归面选择（blast radius）、度量回灌（误诊率 / 泄漏率 / 窗口漂移，观测不判定）、反例/边界击穿（代码审计窗方法选项）。全挂"大厅确定性程序控制 + 代码审计窗方法"名下。
- 单席角色扮演被禁：任何角色必须有独立窗口与独立授权。

### 2.5 非目标 (Non-goals)

- 不定每窗方法论细节与流转参数（修复队列优先级启发式、回归面规则、度量口径——下一步讨论）；本 ADR 冻结拓扑、窗口划分与墙。
- 不跨信任域部署，不引入被审方防伪机制（`ADR-0026` §2.5 保持）。

### 2.6 转 Accepted 门槛（事实源必须是现实，不是愿景）

Proposed 期间文审照常（措辞、拓扑、墙的定义可审可改）。但转 Accepted 必须叠加**实现背书**：G2 人肉窗全链跑通（含打回一次、kill -9 重启位置一致、单均成本基线落盘）+ G3 墙跑通（W1 目录墙 + 钥验签；席用原 seats 机制经配置自动起——自动席本来就有，G3 只加墙，不新建派席机制）之日方可转 Accepted——事实源描述的必须是已落地的现实。W2/W6（G5）与测试骨架（G7）是墙的完整验收，在 Accepted 后、G6 前完成。G6 割接（k3lity 归档，不可逆）必须在 Accepted 之后。

## 3. 产生后果 (Consequences)

- **Up**：形式冗余消除（少一套 harness 面 / 接口 / 运输）；判断权威不因合并降级（窗口独立授权）；墙从约定变机制（进程 + 目录 + CLI 原生隔离可测）；"部署在哪侧"从争议变部署细节；修复通用化（谁修等价）+ 验收独立（Retest 客观）消除"打回作者"人格化残余；行业对标有"保留/优化/新增"底线护栏，既有机制不丢。
- **Down**：同二进制共存失效相关性（大厅崩 = 多目全黑；本地信任域下可接受，明确认账）；窗口同机，靠目录 + 物化裁剪兜底；一个模块多把签名钥的签发/轮换运维成本（独立性从发布轨移到了钥上，成本跟着走）。
- **Reopen when**：① 跨信任域部署成真（墙需升级为防伪）；② W1/W2 测试抓到窗口越墙事故（隔离机制失效）；③ 大厅单进程承载不足（多进程大厅 / 分大厅）；④ 窗口划分与判断类型/对象不再咬合（窗口增删，走新 ADR 而非就地改）。
